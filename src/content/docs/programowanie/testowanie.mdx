# Jak testować program?

## Zrozum od podstaw

Test jest eksperymentem z wcześniej określonym oczekiwaniem. Nie wystarczy uruchomić program i uznać wynik za wiarygodny. Najpierw policz prosty przypadek ręcznie. **Przypadek brzegowy** leży na granicy dozwolonych danych: zero elementów, jeden element, równe wartości albo ostatni poprawny indeks.

Poniżej sprawdzamy sumę liczb od 1 do n dla n nieujemnego. Umawiamy się, że suma dla n = 0 wynosi 0. Dla dużego n trzeba dodatkowo pilnować zakresu typu.

## Przykład prowadzony — kompletny program

Skopiuj ten przykład do osobnego pliku `.cpp`. W kursie używamy C++20. Każdy pełny program ma jedno `main`.

```cpp
#include <iostream>

int main() {
    int n = 5;
    int suma = 0;
    for (int i = 1; i <= n; ++i) suma += i;
    std::cout << suma << '\n';
    return 0;
}
```

### Czytamy kod po kolei

`#include` udostępnia deklaracje z podanego nagłówka; `std::` wskazuje nazwę z biblioteki standardowej. Klamry wyznaczają blok, a średnik kończy instrukcję. `main` jest punktem wejścia; `return 0` oznacza poprawne zakończenie.

1. n jest daną testową, a nie liczbą dobraną automatycznie przez program.
2. suma zaczyna od 0.
3. &lt;= dopuszcza także n, więc dla 5 dodajemy pięć liczb.
4. Porównujemy otrzymane 15 z wynikiem ręcznym 1 + 2 + 3 + 4 + 5.

### Znajdź i napraw błąd

**Błędny fragment — nie kopiuj go jako rozwiązania:**

```cpp
for (int i = 1; i < n; ++i) suma += i;
```

Wersja z &lt; pomija ostatni składnik. Test n = 0 tego nie wykryje, ale n = 1 już tak.

**Poprawiony fragment:**

```cpp
for (int i = 1; i <= n; ++i) suma += i;
```

## Zapamiętaj i sprawdź rozumienie

Test musi mieć oczekiwany wynik i powód wyboru danych. Jeden udany przypadek nie dowodzi poprawności wszystkich ścieżek.

**Powtórka bez patrzenia:** wyjaśnij, dlaczego poprawka w sekcji „Znajdź i napraw błąd” działa. Następnie zmień dane w przykładzie prowadzonym i odtwórz jego stany przed uruchomieniem. Wróć do trzech odpowiedzi powyżej, aby porównać swoje uzasadnienie.

## Rozwinięcie tematu i dotychczasowe ćwiczenia

## Jeden prawidłowy wynik nie dowodzi poprawności

W skrypcie mnożenie przez dodawanie przechodzi test `3 × 4`, lecz pierwotny algorytm nie działa dla pierwszej liczby ujemnej. Z tego wynika ważna zasada: wybieraj testy, które **sprawdzają różne sytuacje**, a nie tylko losowe liczby.

### Klasy testów

- **Typowe:** `3, 4` → 12.
- **Zerowe:** `0, 7` → 0.
- **Ujemne:** `-3, 4` → −12.
- **Oba ujemne:** `-3, -4` → 12.
- **Graniczne:** małe i bardzo duże liczby (zwróć uwagę na możliwe przepełnienie).

## Debugger a test

Test mówi **że coś jest nie tak**. Debugger pomaga ustalić **w którym miejscu** stan zmiennych odbiega od oczekiwań. Te dwie techniki działają razem.

## Przykład błędu logicznego

```cpp
int suma = 0;
for (int i = 1; i < 5; ++i) suma += i;
```

Jeśli polecenie brzmiało „suma liczb od 1 do 5”, ten kod jest błędny: kończy pętlę **przed** `i=5`. Wynik to 10 zamiast 15. Zmiana `i < 5` na `i <= 5` naprawia problem.

## Mini-plan sprawdzenia każdego zadania

1. Zapisz oczekiwany wynik dla prostych danych.
2. Sprawdź najmniejszą dopuszczalną liczbę elementów.
3. Spróbuj danych ujemnych i zerowych, jeśli zadanie ich nie zabrania.
4. Ustal, co powinno się stać, gdy użytkownik wpisze coś nieprawidłowego.
5. Przejdź debuggerem po błędnej ścieżce.

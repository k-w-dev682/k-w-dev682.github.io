# IEEE 754 — jak wyglądają bity `float`

## Zrozum od podstaw

Format binary32 przypomina zapis naukowy liczby: znak, liczba w okolicy 1 oraz potęga 2. W pamięci nie zapisujemy tekstu 2.5, tylko bity trzech pól. Pole wykładnika przechowuje wartość z przesunięciem 127, dzięki czemu zwykłe wykładniki ujemne nie potrzebują osobnego znaku.

Dla liczby znormalizowanej pierwsza jedynka jest domyślna. Pole 23 bitów przechowuje tylko ułamek po niej. Nie wolno stosować tego samego wzoru bez zmian do E = 0 i E = 255.

## Przykład prowadzony — kompletny program

Skopiuj ten przykład do osobnego pliku `.cpp`. W kursie używamy C++20. Każdy pełny program ma jedno `main`.

```cpp
#include <iostream>
#include <cmath>

int main() {
    int znak = 0;
    int poleWykladnika = 128;
    double ulamek = 0.25;
    double wartosc = (znak == 0 ? 1.0 : -1.0)
        * (1.0 + ulamek) * std::pow(2.0, poleWykladnika - 127);
    std::cout << wartosc << '\n';
    return 0;
}
```

### Czytamy kod po kolei

`#include` udostępnia deklaracje z podanego nagłówka; `std::` wskazuje nazwę z biblioteki standardowej. Klamry wyznaczają blok, a średnik kończy instrukcję. `main` jest punktem wejścia; `return 0` oznacza poprawne zakończenie.

1. znak = 0 oznacza dodatnią liczbę; zapis ten ilustruje pola, a nie odczytuje rzeczywistej pamięci float.
2. 128 − 127 daje wykładnik 1.
3. 0.25 odpowiada bitom 01 po kropce.
4. Operator warunek ? a : b wybiera a dla prawdy, b dla fałszu.
5. pow z cmath oblicza 2 do potęgi 1. Otrzymujemy 1 × 1.25 × 2 = 2.5.

### Znajdź i napraw błąd

**Błędny fragment — nie kopiuj go jako rozwiązania:**

```cpp
double skala = std::pow(2.0, poleWykladnika);
```

W polu jest wykładnik przesunięty, a nie rzeczywisty. Pominięcie biasu daje zupełnie inną skalę.

**Poprawiony fragment:**

```cpp
double skala = std::pow(2.0, poleWykladnika - 127);
```

## Przećwicz — od przewidywania do samodzielnej zmiany

### 1. Jak zmieni się 2.5 po ustawieniu S = 1?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

Na −2.5. Pozostałe pola są niezmienione.

</details>

### 2. Jakie E dla rzeczywistego wykładnika −2?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

125, bo −2 + 127 = 125.

</details>

### 3. Co dla E = 0 i niezerowego f?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

Liczba podnormalna ma wartość ze znakiem równą f × 2^(−126), bez ukrytej jedynki. E = 0 i f = 0 koduje zero.

</details>

## Zapamiętaj i sprawdź rozumienie

Binary32: 1 bit znaku + 8 wykładnika + 23 ułamka. E = 255: f = 0 to nieskończoność, f różne od 0 to NaN.

## Rozwinięcie tematu i dotychczasowe ćwiczenia

## Trzy części 32-bitowego `float`

Typowy `float` w formacie **IEEE 754 binary32** zajmuje 32 bity:

```text
┌─────────┬─────────────────┬──────────────────────────┐
│  Znak   │    Wykładnik    │      Część ułamkowa      │
│  1 bit  │     8 bitów     │         23 bity          │
└─────────┴─────────────────┴──────────────────────────┘
```

- **Znak S:** 0 oznacza liczbę dodatnią, 1 oznacza ujemną.
- **Wykładnik E:** liczba z pola ośmiobitowego. Dla zwykłych liczb do obliczenia wykładnika odejmujemy 127.
- **Część ułamkowa f:** informacja o cyfrach po początkowej jedynce w zapisie binarnym liczby znormalizowanej.

## Wzór dla znormalizowanych liczb skończonych

<Eq display tex={String.raw`(-1)^S\cdot(1+f)\cdot 2^{E-127}`} />

| Oznaczenie | Znaczenie |
|---|---|
| `S` | bit znaku: 0 albo 1 |
| `E` | liczba całkowita zapisana w 8-bitowym polu wykładnika |
| `f` | wartość ułamka zapisana w 23-bitowym polu |
| `127` | przesunięcie (*bias*) wykładnika dla formatu binary32 |

Wzór ma zastosowanie, gdy zapis wykładnika `E` jest pomiędzy 1 a 254. **E = 0** i **E = 255** oznaczają przypadki specjalne (m.in. zera, liczby podnormalne, nieskończoności i NaN).

## Ręczny przykład: 2,5

W systemie binarnym:

<Eq display tex={String.raw`2.5_{10}=10.1_2=1.01_2\cdot2^1`} />

1. **Znak:** liczba jest dodatnia, więc `S = 0`.
2. **Wykładnik:** po normalizacji jest równy 1, dlatego zapisujemy `E = 1 + 127 = 128`, czyli `10000000` w systemie binarnym.
3. **Ułamek:** po ukrytej jedynce występuje `01`, a dalej zera.
4. **Wynik:** otrzymujemy 1 bit znaku, 8 bitów wykładnika i 23 bity części ułamkowej.

```text
0 | 10000000 | 01000000000000000000000
```

## Dlaczego 0,1 jest problematyczne?

Liczba `0.1` ma nieskończone rozwinięcie dwójkowe. Format binary32 ma skończoną liczbę bitów, więc zapisuje jej przybliżenie, a nie dokładną wartość matematyczną.

## Interaktywne laboratorium

Wpisz `2.5`, potem `0.1` i sprawdź, jak zmieniają się bity. Używamy kropki jako separatora dziesiętnego, bo tak wygląda zapis liczby w kodzie C++.

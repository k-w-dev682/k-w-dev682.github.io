# Przekroczenie zakresu i wartości specjalne

## Zrozum od podstaw

Każdy typ ma ograniczony zakres. Przepełnienie to wyjście ponad ten zakres, a nie zwykłe obcięcie kilku cyfr. Dla int ze znakiem przepełnienie jest niezdefiniowanym zachowaniem: nie zakładamy przewidywalnego zawijania. Dla unsigned arytmetyka zawija się modulo rozmiar zakresu. Zmiennoprzecinkowe IEEE 754 ma jeszcze inne reguły, m.in. nieskończoności.

numeric_limits pozwala pytać o granice typu. max() to największa wartość, lowest() to najniższa. Dla float min() oznacza najmniejszą dodatnią wartość znormalizowaną, a nie najbardziej ujemną.

## Przykład prowadzony — kompletny program

Skopiuj ten przykład do osobnego pliku `.cpp`. W kursie używamy C++20. Każdy pełny program ma jedno `main`.

```cpp
#include <iostream>
#include <limits>

int main() {
    int a = 1000000;
    int b = 1000000;
    long long bezpieczniej = 1LL * a * b;
    std::cout << bezpieczniej << '\n';
    std::cout << std::numeric_limits<int>::max() << '\n';
    return 0;
}
```

### Czytamy kod po kolei

`#include` udostępnia deklaracje z podanego nagłówka; `std::` wskazuje nazwę z biblioteki standardowej. Klamry wyznaczają blok, a średnik kończy instrukcję. `main` jest punktem wejścia; `return 0` oznacza poprawne zakończenie.

1. a i b mieszczą się w typowym 32-bitowym int.
2. 1LL jest literałem long long; pierwsze mnożenie zachodzi już w szerszym typie.
3. Iloczyn 1000000000000 mieści się w long long. Sama nazwa bezpieczniej nie obiecuje braku przepełnienia dla wszystkich danych.
4. limits udostępnia granicę konkretnej implementacji int.

### Znajdź i napraw błąd

**Błędny fragment — nie kopiuj go jako rozwiązania:**

```cpp
long long wynik = a * b;
```

W pierwszej wersji mnożenie następuje w int jeszcze przed przypisaniem. Szersza zmienna docelowa nie chroni wcześniejszego działania.

**Poprawiony fragment:**

```cpp
long long wynik = 1LL * a * b;
```

## Rozwinięcie tematu i dotychczasowe ćwiczenia

## Dlaczego nawet `float` ma granice?

`float` nie ma nieskończenie dużej liczby wykładników. Dla wartości zbyt dużej pojawia się **przepełnienie** (*overflow*), np. matematycznie skończony wynik może dać `+inf` w arytmetyce IEEE 754.

```cpp
#include <iostream>
#include <limits>
int main() {
    float x = 1e20f;
    std::cout << x * x << '\n';  // zwykle inf
}
```

Dla wartości bardzo bliskich zera może wystąpić **underflow** i utrata dokładności. W formacie IEEE 754 istnieje również `NaN` — „Not a Number”, np. dla niektórych niedozwolonych działań zmiennoprzecinkowych.

## Ważne rozróżnienie

- Przepełnienie `float` i `double` **nie działa** tak samo jak przepełnienie liczb całkowitych ze znakiem.
- `pow(x, 2)` może używać arytmetyki `double`, dlatego w konkretnym przykładzie pozwoli na zakres większy niż `x*x` liczone jako `float`. Nie jest to dowód, że `pow` nigdy nie przepełni zakresu.
- Nie zakładaj, że `long double` ma zawsze 12 bajtów — zależy od kompilatora i platformy.

## Zadanie

Sprawdź `std::numeric_limits<float>::max()` i `std::numeric_limits<double>::max()`. Wyjaśnij, dlaczego `double` zwykle mieści znacznie większe wartości.

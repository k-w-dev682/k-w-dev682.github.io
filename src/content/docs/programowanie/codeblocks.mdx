# Code::Blocks i pliki projektu

## Zrozum od podstaw

Edytor jest jak zeszyt z kodem. Kompilator sprawdza i tłumaczy ten kod, a terminal pokazuje działanie programu. IDE łączy te narzędzia, ale samo otwarcie pliku nie oznacza, że istnieje już nowy program wykonywalny. Najważniejszy nawyk: po zmianie kodu zapisz plik i zbuduj projekt.

Utwórz projekt aplikacji konsolowej C++, wybierz konfigurację Debug i upewnij się, że plik z `main` należy do projektu. Nazwy menu mogą zależeć od wersji. W dzienniku budowania sprawdzisz, czy uruchomiono kompilator i czy zakończył bez błędu.

## Przykład prowadzony — kompletny program

Skopiuj ten przykład do osobnego pliku `.cpp`. W kursie używamy C++20. Każdy pełny program ma jedno `main`.

```cpp
#include <iostream>

int main() {
    std::cout << "Wersja 1" << '\n';
    return 0;
}
```

### Czytamy kod po kolei

`#include` udostępnia deklaracje z podanego nagłówka; `std::` wskazuje nazwę z biblioteki standardowej. Klamry wyznaczają blok, a średnik kończy instrukcję. `main` jest punktem wejścia; `return 0` oznacza poprawne zakończenie.

1. Zapisz kompletny program jako main.cpp. Rozszerzenie .cpp oznacza plik źródłowy C++.
2. `std::cout` wysyła napis do konsoli. Cudzysłowy obejmują cały napis, średnik kończy instrukcję.
3. Zbuduj program i uruchom go. Następnie zamień 1 na 2, zapisz i ponownie zbuduj.

### Znajdź i napraw błąd

**Błędny fragment — nie kopiuj go jako rozwiązania:**

```cpp
std::cout << "Wersja 2;
```

Brakuje zamykającego cudzysłowu. Kompilator nie wie, gdzie kończy się tekst; napraw najpierw pierwszy komunikat, potem buduj ponownie.

**Poprawiony fragment:**

```cpp
std::cout << "Wersja 2";
```

## Zapamiętaj i sprawdź rozumienie

Zapisz → zbuduj → sprawdź komunikaty → uruchom. Kopiuj cały przykład do jednego pliku; nie łącz kilku funkcji main.

**Powtórka bez patrzenia:** wyjaśnij, dlaczego poprawka w sekcji „Znajdź i napraw błąd” działa. Następnie zmień dane w przykładzie prowadzonym i odtwórz jego stany przed uruchomieniem. Wróć do trzech odpowiedzi powyżej, aby porównać swoje uzasadnienie.

## Rozwinięcie tematu i dotychczasowe ćwiczenia

## Czym jest IDE?

**IDE** (*Integrated Development Environment*) to środowisko łączące edytor kodu, uruchamianie kompilatora, debugowanie i zarządzanie projektem. Skrypt posługuje się Code::Blocks. Nie jest ono językiem C++: kod możesz pisać również w innym edytorze.

## Prosty sposób pracy

1. Utwórz nową aplikację konsolową C++ albo plik z rozszerzeniem `.cpp`.
2. Zapisz plik, np. `zadanie1.cpp`.
3. Wpisz program i uruchom **Build** (kompilację z linkowaniem).
4. Popraw komunikaty o błędach, jeśli się pojawią.
5. Uruchom zbudowany program i wpisz dane testowe.

W Code::Blocks często spotkasz skrót `F9` dla „Build and run”; przypisanie klawiszy zależy jednak od konfiguracji. Nie musisz używać dokładnie takiej wersji programu jak w starym skrypcie.

## Różnica między plikiem a projektem

| Plik `.cpp` | Projekt IDE |
|---|---|
| Zawiera kod źródłowy | Zawiera ustawienia budowania i odwołania do plików |
| Da się go skompilować | Ułatwia pracę z wieloma plikami |
| Łatwy na początek | Przydatny przy większych aplikacjach |

## Na co uważać?

- Komunikat `missing terminating " character` zwykle oznacza niedomknięty napis.
- Komunikat o błędzie w **kolejnej linii** nie musi wskazywać rzeczywistej przyczyny.
- `Build` to nie to samo co `Run`: uruchomienie starego pliku wykonywalnego może nie uwzględniać zmian w kodzie.
- Polskie znaki w konsoli zależą od kodowania źródła, terminala i środowiska. Polecenia `chcp` ze skryptu są specyficzne dla Windows i nie są uniwersalnym rozwiązaniem.

## Małe ćwiczenie

Wpisz w kodzie `std::cout << "Hej;` (bez drugiego cudzysłowu). Uruchom budowanie i porównaj wskazaną linię z faktyczną przyczyną błędu. Potem popraw kod.

# Dlaczego `0.1` nie jest dokładne?

## Zrozum od podstaw

Tak jak za przecinkiem dziesiętnym są dziesiąte i setne, za kropką binarną są połówki, ćwiartki i ósme. Ułamek ma skończony zapis dwójkowy, jeżeli po skróceniu jego mianownik jest potęgą dwójki. Dlatego 3/8 jest łatwe, a 1/10 wymaga nieskończonego rozwinięcia.

Przy mnożeniu ułamka przez 2 część całkowita wyniku daje kolejny bit. Następnie odejmujemy tę część i powtarzamy z resztą. Poniżej 0.625 jest dokładnie reprezentowalne, więc trzy kroki kończą się zerową resztą.

## Przykład prowadzony — kompletny program

Skopiuj ten przykład do osobnego pliku `.cpp`. W kursie używamy C++20. Każdy pełny program ma jedno `main`.

```cpp
#include <iostream>

int main() {
    double reszta = 0.625;
    for (int i = 0; i < 3; ++i) {
        reszta *= 2;
        int bit = static_cast<int>(reszta);
        std::cout << bit;
        reszta -= bit;
    }
    return 0;
}
```

`#include` udostępnia deklaracje z podanego nagłówka; `std::` wskazuje nazwę z biblioteki standardowej. Klamry wyznaczają blok, a średnik kończy instrukcję. `main` jest punktem wejścia; `return 0` oznacza poprawne zakończenie.

1. reszta zaczyna od 5/8.
2. Mnożenie przez 2 przesuwa następną cyfrę binarną przed kropkę.
3. Konwersja do int odrzuca ułamek; dla wartości od 0 do mniej niż 2 daje 0 lub 1.
4. Po wypisaniu bitu odejmujemy go, aby ponownie zostać z samym ułamkiem.

### Znajdź i napraw błąd

**Błędny fragment — nie kopiuj go jako rozwiązania:**

```cpp
reszta *= 2; // brak odjęcia części całkowitej
```

Jeśli zachowasz część całkowitą, następny krok nie będzie już przetwarzaniem ułamka i może dać cyfrę większą od 1.

**Poprawiony fragment:**

```cpp
reszta *= 2;
int bit = static_cast<int>(reszta);
reszta -= bit;
```

## Przećwicz — od przewidywania do samodzielnej zmiany

### 1. Dlaczego 0.25 jest dokładne?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

To 1/4 = 2 do potęgi −2, więc zapis 0.01₂ kończy się po dwóch bitach.

</details>

### 2. Co daje 0.11₂?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

1/2 + 1/4 = 0.75.

</details>

### 3. Czy ten algorytm na double udowadnia okresowość 0.1?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

Nie: double już zawiera zaokrąglenie. Dowód okresowości prowadź na dokładnych ułamkach, jak w tabeli poniżej.

</details>

## Zapamiętaj i sprawdź rozumienie

Skończona pamięć wymaga zaokrąglenia nieskończonego rozwinięcia. To cecha reprezentacji, a nie awaria procesora.

## Rozwinięcie tematu i dotychczasowe ćwiczenia

## Zaskoczenie ze skryptu

`0.5₁₀ = 0.1₂`, więc ma dokładny zapis. Ale `0.1₁₀` ma nieskończone, okresowe rozwinięcie binarne:

```text
0.1₁₀ ≈ 0.00011001100110011...₂
0.3₁₀ ≈ 0.01001100110011001...₂
0.5₁₀ = 0.1₂
```

W starym skrypcie zapis binarny `0.3` jest w tabeli nieprawidłowo powtórzony po `0.1`. Tutaj podajemy poprawne rozwinięcia.

## Metoda mnożenia ułamka przez 2

Aby odtworzyć kolejne cyfry binarne liczby `0.1`, mnożymy część ułamkową przez 2. **Część całkowita** wyniku staje się następnym bitem, a pozostały ułamek mnożymy ponownie.

| Krok | Mnożenie | Bit | Pozostała część |
|---:|---|---:|---:|
| 1 | 0.1 × 2 = 0.2 | 0 | 0.2 |
| 2 | 0.2 × 2 = 0.4 | 0 | 0.4 |
| 3 | 0.4 × 2 = 0.8 | 0 | 0.8 |
| 4 | 0.8 × 2 = 1.6 | 1 | 0.6 |
| 5 | 0.6 × 2 = 1.2 | 1 | 0.2 |

Widzisz powrót do `0.2` — pojawia się okres. Ponieważ format ma ograniczoną liczbę bitów, zapis trzeba zaokrąglić.

## Zadanie

Wykaż, że `0.25` ma dokładny zapis binarny. Wynik: `0.01₂`, bo `0.25 = 1/4`.

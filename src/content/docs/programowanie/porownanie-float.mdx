# Jak bezpieczniej porównywać `double`

## Zrozum od podstaw

Porównanie == odpowiada na pytanie o równość wartości według reguł danego typu. Nie porównuje po prostu wszystkich bitów: +0.0 i −0.0 są równe mimo innego bitu znaku, a NaN nie jest równy nawet sobie. Gdy oczekujesz wyniku przybliżonego, możesz zamiast tego sprawdzić, czy odległość mieści się w dozwolonym błędzie.

**Tolerancja bezwzględna** jest stałą odległością, np. 0.001. **Względna** odnosi błąd do skali wartości. Tolerancję dobiera się do zadania; epsilon typu nie jest uniwersalną dokładnością wszystkich obliczeń.

## Przykład prowadzony — kompletny program

Skopiuj ten przykład do osobnego pliku `.cpp`. W kursie używamy C++20. Każdy pełny program ma jedno `main`.

```cpp
#include <iostream>
#include <cmath>

int main() {
    double a = 0.1 + 0.2;
    double b = 0.3;
    double tolerancja = 1e-9;
    bool blisko = std::abs(a - b) <= tolerancja;
    std::cout << std::boolalpha << blisko << '\n';
    return 0;
}
```

### Czytamy kod po kolei

`#include` udostępnia deklaracje z podanego nagłówka; `std::` wskazuje nazwę z biblioteki standardowej. Klamry wyznaczają blok, a średnik kończy instrukcję. `main` jest punktem wejścia; `return 0` oznacza poprawne zakończenie.

1. a powstaje przez dodawanie, b przez reprezentację literału; mogą różnić się o drobne zaokrąglenie.
2. 1e-9 oznacza 0.000000001.
3. abs z cmath mierzy nieujemną odległość, więc kolejność a i b nie zmienia kryterium.
4. boolalpha wypisuje true/false zamiast 1/0.

### Znajdź i napraw błąd

**Błędny fragment — nie kopiuj go jako rozwiązania:**

```cpp
bool blisko = a - b <= tolerancja;
```

Bez abs każda duża ujemna różnica przejdzie test. Liczy się odległość, nie kierunek.

**Poprawiony fragment:**

```cpp
bool blisko = std::abs(a - b) <= tolerancja;
```

## Przećwicz — od przewidywania do samodzielnej zmiany

### 1. Czy 1 i 100 są bliskie przy tolerancji 0.01?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

Nie. Odległość to 99; bez abs różnica 1 − 100 mogłaby błędnie przejść test.

</details>

### 2. Czy bliskość jest zawsze przechodnia?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

Nie. Przy tolerancji 1 liczby 0 i 0.75 są bliskie, 0.75 i 1.5 też, ale 0 i 1.5 już nie.

</details>

### 3. Co zrobić z NaN i nieskończonościami?

<details>

</details>

## Zapamiętaj i sprawdź rozumienie

Dobieraj kryterium do znaczenia wyniku. Przybliżona równość nie jest tym samym co == i nie nadaje się bezmyślnie do porządkowania.

**Powtórka bez patrzenia:** wyjaśnij, dlaczego poprawka w sekcji „Znajdź i napraw błąd” działa. Następnie zmień dane w przykładzie prowadzonym i odtwórz jego stany przed uruchomieniem. Wróć do trzech odpowiedzi powyżej, aby porównać swoje uzasadnienie.

## Rozwinięcie tematu i dotychczasowe ćwiczenia

## `==` działa, ale często nie oznacza tego, czego chcemy

Dla wartości reprezentowanych przybliżeniami pytanie „czy są równe według reguł porównania wartości?” jest inne niż „czy wyniki można uznać za dostatecznie bliskie?”.

```cpp
#include <cmath>
#include <algorithm>

bool bliskie(double a, double b) {
    const double eps = 1e-9;
    return std::abs(a - b) <= eps *
           std::max({1.0, std::abs(a), std::abs(b)});
}
```

`std::abs(a-b)` to odległość między wynikami. Po prawej określamy granicę błędu zależną od ich skali (dla liczb bliskich zeru także od stałej podstawowej).

## Przykład

Jeśli wynik to `0.30000000000000004`, a oczekujesz `0.3`, różnica jest bardzo mała — ale niezerowa. Dobrane `eps` może uznać oba wyniki za „bliskie”.

## Ważne ograniczenie

Nie istnieje jedna tolerancja dobra do wszystkich zadań. Dla pomiarów laboratoryjnych i symulacji numerycznych skala błędu może być inna. A jeśli sprawdzasz, czy liczba jest **dokładnie** zero jako znacznik sterujący, użycie tolerancji może zmieniać znaczenie zadania.

## Zadanie

Dlaczego `std::abs(a-b) < 0.0001` może nie nadawać się do porównania bardzo dużych liczb? Bo błąd bezwzględny trzeba odnieść do skali wartości.

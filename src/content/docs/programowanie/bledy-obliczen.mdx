# Błędy zaokrągleń i pętla, która nie kończy

## Zrozum od podstaw

Zaokrąglenie może wystąpić już przy zapisaniu liczby i ponownie przy każdym działaniu. To jak wielokrotne odmierzanie niedokładną miarką: końcowy błąd zależy także od sposobu liczenia. Odejmowanie prawie równych liczb może usunąć wspólne cyfry i ujawnić wcześniej mało widoczny błąd.

Oddziel decyzję o liczbie powtórzeń od wartości przybliżonej. Gdy zadanie mówi o dziesięciu próbkach, użyj dziesięciu kroków z licznikiem całkowitym. Nie czekaj, aż przybliżona suma przypadkiem będzie dokładnie równa granicy.

## Przykład prowadzony — kompletny program

Skopiuj ten przykład do osobnego pliku `.cpp`. W kursie używamy C++20. Każdy pełny program ma jedno `main`.

```cpp
#include <iostream>
#include <iomanip>

int main() {
    double x = 1.0;
    for (int i = 0; i < 10; ++i) {
        x -= 0.1;
    }
    std::cout << std::setprecision(17) << x << '\n';
    return 0;
}
```

### Czytamy kod po kolei

`#include` udostępnia deklaracje z podanego nagłówka; `std::` wskazuje nazwę z biblioteki standardowej. Klamry wyznaczają blok, a średnik kończy instrukcję. `main` jest punktem wejścia; `return 0` oznacza poprawne zakończenie.

1. x zaczyna od dokładnego 1.
2. Licznik i zapewnia dokładnie dziesięć obiegów.
3. Każde odejmowanie używa przybliżenia 0.1 i może ponownie zaokrąglić wynik.
4. Wynik na typowym binary64 jest bliski zeru, ale może nie być zerem. To nie zmienia liczby obiegów.

### Znajdź i napraw błąd

**Błędny fragment — nie kopiuj go jako rozwiązania:**

```cpp
while (x != 0.0) { x -= 0.1; }
```

Dokładne zero może nigdy nie wystąpić. Licznik całkowity spełnia wymaganie liczby kroków niezależnie od błędu arytmetyki.

**Poprawiony fragment:**

```cpp
for (int i = 0; i < 10; ++i) { x -= 0.1; }
```

### 3. Jak wyznaczyć 11 punktów od 0 do 1?

<details>
<summary>Sprawdź odpowiedź i uzasadnienie</summary>

Dla i od 0 do 10 włącznie oblicz x = i / 10.0. Punkty są przybliżone, ale jest ich dokładnie jedenaście.

</details>

## Zapamiętaj i sprawdź rozumienie

Błąd wyniku i błąd sterowania pętlą to osobne problemy. Licznik int rozwiązuje drugi, nie usuwa pierwszego.

**Powtórka bez patrzenia:** wyjaśnij, dlaczego poprawka w sekcji „Znajdź i napraw błąd” działa. Następnie zmień dane w przykładzie prowadzonym i odtwórz jego stany przed uruchomieniem. Wróć do trzech odpowiedzi powyżej, aby porównać swoje uzasadnienie.

## Rozwinięcie tematu i dotychczasowe ćwiczenia

## Pułapka z materiału

Skrypt pokazuje pętlę, w której `float x=1.0` jest zmniejszany o `0.1`, aż `x==0`. To jest **niebezpieczny warunek** — ze względu na błędy reprezentacji binarnej nie można na nim polegać.

```cpp
float x = 1.0f;
while (x != 0.0f) {
    x -= 0.1f; // może nigdy nie być dokładnie 0
}
```

Mimo że w matematyce po dziesięciu odejmowaniach otrzymasz zero, na komputerze wartość może pozostać maleńkim niezerowym przybliżeniem (lub stać się ujemna).

## Poprawka: licz iteracje

```cpp
for (int i = 0; i < 10; ++i) {
    double x = 1.0 - (i + 1) * 0.1;
    std::cout << x << '\n';
}
```

Licznik całkowity jest tutaj pewną informacją o liczbie kroków. Wynik obliczenia nadal może być przybliżony, ale pętla wykona **dokładnie dziesięć iteracji**.

## Co testować?

- Powtarzane dodawanie małych liczb.
- Odejmowanie liczb podobnej wielkości (utrata cyfr znaczących).
- Zmianę kolejności operacji — przez zaokrąglenia może zmienić wynik.

:::caution[Wnioski]
Nie zakładaj, że `0.1 + 0.2 == 0.3` zawsze zadziała. Gdy chodzi o przybliżoną równość, zastosuj odpowiednią tolerancję dla skali obliczenia.
:::
